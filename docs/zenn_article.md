## はじめに

ノルウェー政府年金基金（NBIM）、サウジアラビアの公共投資基金（PIF）、シンガポールのGIC。こうした政府系ファンド（SWF）は、数十年単位の長期目線で日本株に投資しています。

その足跡は公開されています。EDINETの大量保有報告書や、NBIMの全保有銘柄データです。ただし、個人投資家が日々追いかけるのは現実的ではありません。

**Sovereign Lens** は、この「プロの足跡」をAIエージェントが自律的に集めて分析し、利用者の資産サイズに合わせた投資戦略のたたき台にするシステムです。

- デモ：https://sovereign-lens-mhdvlbrwja-an.a.run.app
- GitHub：https://github.com/YasuhitoYanagisawa/sovereign-lens

## 解決したい課題

- **情報が分散している。** 大量保有報告書はXBRLやPDF、NBIMのデータは英語のJSONです。
- **「誰が持っているか」だけでは役に立たない。** 個人が知りたいのは次のようなことです。
  - いくらで買ったのか
  - いつから持っているのか、まだ買い増しているのか、売り始めたのか
  - なぜ買ったのか（純投資なのか、経営に提案するつもりなのか）
  - 今は買い時なのか、自分の資金で何株買えばいいのか
- **真似ると偏る。** 例えばPIFの日本株は、任天堂・カプコン・ネクソン・コーエーテクモ・スクウェア・エニックスなど、ゲーム株に集中しています。
- **「大株主＝良いサイン」とは限らない。** MSワラントの引受け先（資金調達型）が5%超を持っている銘柄は、株を市場で売るのが前提です。

## できること

| 機能 | 内容 |
|---|---|
| ファンド保有の収集 | EDINETの大量保有報告書（docType 350/360）とNBIM公開APIから、政府系ファンドの日本株を集めます |
| 推定取得単価 | 報告書の「取得資金合計 ÷ 保有株数」を株式分割で調整して算出し、現在値と比べます |
| 比率の推移 | 初回の比率・直前の比率・ピーク比率を追い、「どれだけ買い増したか」「ピークからどれだけ売ったか」を判定します |
| 保有目的 | 報告書の「保有目的」「重要提案行為等」を読み、純投資／重要提案行為等／経営関与／政策投資・提携／資金調達の引受けに分類します |
| Conviction Score | 保有比率25＋ファンドの重なり20＋保有期間20＋比率の推移15＋取得コスト比15＋保有目的5の100点満点 |
| 買い時判定 | 取得単価との差、52週高値からの下落、200日移動平均、ファンドの売買から「買い場候補／分割で買い／様子見／見送り」を判定 |
| 戦略の作成 | コア（TOPIX）＋ファンド追随の個別株＋現金。単元株か単元未満株かを判定し、分割購入の計画まで出します |
| 物言う株主・警告 | 村上系・エフィッシモ・オアシス・エリオットなど実績のあるアクティビストは別カテゴリ（スイッチで採用）。EVO FUNDなど資金調達型が持つ銘柄は「買わない方がよい」と警告し、戦略に入れません |
| 保有管理 | 買った銘柄の損益と、「ファンドが売り始めた」アラートを確認できます（データはブラウザ内だけに保存） |

## データから見えたこと

- **PIFのゲーム株は2026年1月に移管されていた。** カプコン・ネクソン・コーエーテクモ・東映・スクウェア・エニックスの株を、グループ会社のAyar First Investmentへ無対価で移管していました。
- **推定取得単価で「プロより高く買っていないか」がわかる。** 例えばPIFのネクソンは約3,005円で、現在値がそれより安ければ「買い場候補」になります。逆にカプコンは推定取得単価の約3倍で「見送り推奨」です。
- **NBIMの数字には注意が必要。** ノルウェー銀行の取得資金には貸株などの回転が含まれるため、単価の推定には使えません。システムでは「推定不可」と明示しています。
- **保有目的の書き方には差がある。** 政府系ファンドはほぼ「純投資」ですが、アクティビストは「重要提案行為等を行うことがある」と明記しています。これがあると増配・自社株買い・TOBなどのイベントが起きやすいため、スコアで加点しています。

## アーキテクチャ

![](https://raw.githubusercontent.com/YasuhitoYanagisawa/sovereign-lens/main/docs/architecture.png)

- **Cloud Run**：FastAPIで、Web UI、REST、SSEストリームを提供
- **Agent Development Kit（ADK）**：オーケストレーター、理由調査エージェント（Google検索グラウンディング）、独立審査エージェント
- **Gemini 3.8 Flash（Vertex AI）**：思考レベルLOW。起動時に利用可能なモデルを確認し、自動でフォールバック
- **Cloud Scheduler + Cloud Storage**：EDINETの自動同期
- **Cloud Trace / Cloud Logging / Secret Manager**

### 自律性：エージェントが自分で進める

利用者が金額・リスク・期間を入れると、オーケストレーターが次の手順を自分で判断して進めます。

1. Conviction Score で候補を採点
2. 上位銘柄の資料（保有者・取得コスト・比率の推移・保有目的）を確認
3. 「なぜそのファンドが買ったか」をGoogle検索で調査（事実と推測を分けて出典付き）
4. 決定論的エンジンで配分を計算
5. 独立審査エージェントが集中リスクなどを指摘。必要なら除外銘柄を変えて作り直す

配分の即時試算は数秒で表示し、レポートは書けた部分から順にストリーミングで表示します。

### EDINETの自動同期：新しい報告をすぐ反映

大量保有報告書は随時提出されます。そこで Cloud Scheduler が1日2回、トークン認証付きの同期エンドポイントを呼びます。

1. 追跡しているファンドの新しい報告書をEDINET APIで探す
2. CSVから、保有比率・直前の保有比率・取得資金・保有目的・重要提案行為等を要素IDで抽出
3. 初回比率・ピーク比率・履歴とあわせて Cloud Storage に保存
4. 全インスタンスがそれを読み込み、再デプロイなしでスコア・買い時判定・戦略に反映

ピークの半分以下まで売られた銘柄は「大きく売却中」として、戦略の候補から外します。

### 制御：LLMに数字を作らせない

配分の数値はすべて Python のツールが計算します。

- 1銘柄・1業種の上限、現金比率の下限、リスク別の銘柄規模フィルタはコードで強制しています。
- 金額・リスク・期間の全組み合わせで、ガードレールが守られることをテストで確認しています。

### ガバナンス：ADK Plugin

`BasePlugin` を継承した `GovernancePlugin` で、すべてのツール呼び出しを通しています。

- 入力のプロンプトインジェクション検知と、発注・認証情報の要求のブロック
- ツールの許可リストと、ツールごとの呼び出し上限
- 構造化監査ログ（Cloud Logging）
- 理由調査結果の12時間キャッシュ（速度とコストの両立）

さらに、発注機能そのものを持たせていません。プランは人が確認・承認し、自分の証券口座で実行する設計です。

### 審査役のモデルについて

独立審査エージェントは、同じモデル系統どうしで誤りを見逃しにくくするため、別ベンダーのモデル（GMI Cloud上のDeepSeekなど）に切り替えられるように作ってあります。ただし **GMI Cloudは予備として組み込んであるだけで、現在は使用していません**（審査もGeminiで行っています）。環境変数で切り替えられ、応答がないときは自動でGeminiに戻ります。

### テストのしやすさ

ADKの `BaseLlm` を継承した「台本どおりに動く偽LLM」を作りました。これを使い、Runner → Plugin → ツール → セッション状態までの一連の流れを、ネットワークなしでテストしています。EDINETのCSVパーサーや保有目的の分類、比率の推移のスコアも、実際の報告書の形式でテストしています（54件）。

政府系ファンドの長期目線を、すべての個人投資家に。Sovereign Lens は、そのための「レンズ」です。
